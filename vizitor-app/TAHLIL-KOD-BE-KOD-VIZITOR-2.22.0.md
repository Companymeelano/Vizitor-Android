# تحلیل کد‌به‌کد نسخهٔ ۲٫۲۲٫۰ — خانهٔ «M•A Report» (نسخهٔ انحصاری)

> خواسته: «نسخه دقیقا مشابه فایل `app-debug-40.apk.zip` را برای من بساز و فقط اتصال به
> دیتابیس و فراخوانی اطلاعات را راه‌اندازی کن.»
> مبنای مرجع: همان APK پیوست (`ir.atiran.hamrah.viewer`) که در `refs/app-debug-40/`
> تحلیل شده است؛ در بازخوانی این دور معلوم شد کل رابط مرجع در کلاس‌های `DemoScreenKt` است —
> یعنی خودِ مرجع هم «نمای نمایشی» است و فقط اتصال SQL آن واقعی است.

## ۱) فایل‌های این نسخه

| فایل | نقش |
|---|---|
| `ui/screens/manager/MReportHome.kt` (تازه، ~۱٬۴۶۰ خط) | خانهٔ «M•A Report»: نوار بالا، شش بخش، همهٔ کارت‌ها/نمودارها، برگهٔ «تنظیمات هوشمند» و منطق خواندن داده |
| `ui/screens/manager/MaManagerScreen.kt` (ویرایش) | در نسخهٔ انحصاری، خانه اول نمایش داده می‌شود و پنج صفحهٔ کاری موتور گزارش پشت آن باز می‌شوند (`hub` + `homeRefresh`) |
| `app/build.gradle.kts` | شمارهٔ ساخت ۲۱۸۱۸ و نام نسخه‌ها `2.22.0-direct` / `2.22.0-report` |
| `.github/workflows/build-vizitor-app.yml` | `APP_VERSION=2.22.0`، متن ریلیز هر دو برنامه، بازرسی DEX/رشته‌های تازه |

## ۲) ساختار خانه (`MReportHome`)

```
MReportHome(onExit, onOpen, refreshSignal)
├── MaTopBar("M•A Report", eyebrow="Intelligent Reporting Experience")
│     onBack=onExit · onFilter= برگهٔ تنظیمات هوشمند · onAlert= شمارندهٔ واقعی اعلان‌ها
│     onSearch= مرور داده‌ها · chip= «متصل — حالت» / «وصل نشده»
├── MaNavStrip(شش بخش): overview · customers · products · treasury · reports · alerts
├── LazyColumn → when(tab) → homeOverview/customers/products/treasury/reports/alerts
│     و در پایان هر برگه: MaHomeFooter («★ …» + MEELANO STUDIO DESIGN + میلاد یعقوبی)
└── MaSmartSheet(title="تنظیمات هوشمند") با دو گروه مرجع
      «مدیریت هوشمند و دسترسی سریع»: مرور/جست‌وجو · اتصال و همگام‌سازی · دریافت مجدد
      «داده، اتصال و خروجی‌های کاربردی»: فهرست جدول‌ها · اتصال جداول · گزارش‌ها ·
        اشتراک · کپی · اعلان‌ها
```

نکتهٔ فنی مهم: تابع‌های برگه‌ها `LazyListScope` هستند و **نباید** `@Composable` باشند
(فراخوانی از داخل `LazyColumn` کامپوزبل نیست)؛ به همین دلیل پالت رنگ داخل خودِ `item { }`
خوانده می‌شود. همین نکته در CI نسخهٔ اول را رد کرد و در نسخهٔ دوم اصلاح شد.

## ۳) اتصال بین خانه و صفحه‌های کاری

| کلید `onOpen` | صفحه‌ای که باز می‌شود |
|---|---|
| `conn` | «تنظیم اتصال» (دو نشانی داخلی/اینترنت، پورت، دیتابیس، کاربر، رمز، کاوش‌ها و عیب‌یابی) |
| `map` | «اتصال جداول» (نگاشت پنج بخش + تشخیص خودکار) |
| `data` | «مرور داده‌ها» (صفحه‌بندی + جست‌وجوی زنده + جزئیات رکورد) |
| `overview` | «نمای کلی» موتور (فهرست جدول‌ها، شمار رکورد، حجم دیتابیس) |
| `report` | «گزارش‌ها» موتور (مجموع مبلغ، برترین‌ها، آخرین رکوردها) |

بازگشت از هر صفحه: `st.hub = false; st.homeRefresh += 1` ⇒ خانه دوباره داده می‌خواند.

## ۴) جریان فراخوانی اطلاعات (`maHomeLoad`)

```
MaSectionStore.load()  → نگاشت پنج بخش (customer/product/invoice/check/bank)
MaSqlEngine.isConnected ?
   ├── نه  → همهٔ شاخص‌ها null و کارت‌ها «—»/متن مرجع (هیچ عدد ساختگی)
   └── بله → برای هر بخش نگاشت‌شده:
            MaMapping.rolesOf(ref)   ← تشخیص خودکار ستون نام/مبلغ/تاریخ/کد
            MaSqlEngine.count        ← شمار رکورد
            MaSqlEngine.sumOf        ← مجموع ستون مبلغ
            MaSqlEngine.topBy/page   ← برترین‌ها یا صفحهٔ اول
            maMonthly(...)           ← جمع مبلغ‌ها به تفکیک ماه (برای نمودار روند)
```

هر کوئری جداگانه در `maTry { }` اجرا می‌شود تا خطای یک جدول، بقیهٔ گزارش را نخواباند؛
همهٔ کوئری‌ها فقط `SELECT`/کاتالوگ سیستم‌اند (قاعدهٔ ثابت مرجع: اتصال فقط-خواندنی).

## ۶) محدودهٔ این دور (عامدانه)

* «فقط اتصال به دیتابیس و فراخوانی اطلاعات» فعال شد — بقیه نمایشی است و برنامه خودش
  این را می‌گوید (متن مرجع روی صفحه، بدون ادعای نادرست).
* ویترین، سبد خرید، ثبت ویزیت، چت، همگام‌سازی پس‌زمینه و دادهٔ نمونه در نسخهٔ انحصاری
  اجرا نمی‌شوند (طعم `mreport` فقط `SecureDbStore` و `MaSectionStore` را بالا می‌آورد).
* بستهٔ `ir.atiran.mreport` جداست ⇒ کنار «آتیران ویزیتور» نصب می‌شود؛ کلید امضا یکی است
  ⇒ به‌روزرسانی درجا.
